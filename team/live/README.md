# Anur Living Map, the server

One small server holds the map; every open window draws the same one, and a click in one window (a Dispute, an Approve) moves them all. With `--project <repo>` the map is drawn from that repo's own files; without it, it plays the plan-first story from `seed.json`. What people decide is written to `outbox.md`, which a Claude Code chat can read back. A linked chat's listener (`wait.js`) gets what is meant for that chat, and with it `chat-rules.md`, the rules for answering it, whenever that chat has not had this version of them yet (otherwise one line says they are unchanged), so a chat that started before an update still works from the current rules; `GET /api/rules` gives the same text, and `open-map.sh` prints it when it opens a map.

```bash
node server.js 4323 --project <repo>    # http://localhost:4323/<repo folder name>/
node server.js                          # the plan-first story, http://localhost:4322
```

- Open `http://localhost:4322` as yourself, and `http://localhost:4322/?as=Priyanka` in a second window as her.
- **→** / **Space** / **Next ›** moves the story forward for everyone; **←** / **Back** moves it back; the buttons on the cards (Dispute, Confirm, Approve, Flag to Sam) are real clicks that set the step and write to the outbox.
- `?rec` hides the controls; `?chat` shows a mock chat pane (off by default: the real Claude Code chat sits beside the map).
- `curl -s localhost:4322/api/outbox` is what the chat hears; `POST /api/act {"type":"reset"}` starts the story over.
- Each address is its own map: `http://localhost:4322/gtm/` is a map called `gtm`, with its API under it (`/gtm/api/state`, `/gtm/api/act`). It starts empty, keeps its state in `maps/gtm/`, and fills from the plans drawn on it.
- On the home page, owners can move named maps and maps linked to code folders to **Trash**, even before opening them. **Undo** restores a just-moved map; **Trash → Restore** restores it later, including older locally archived maps. Code files and online copies are kept. Trashed maps stay out of the list across restarts and old links, and Restore never overwrites another map.
- With `--project`, `/` is a list of every map to pick from (`/api/maps` gives the same list); the project's own map is at `/<project folder>/`, and `/api/...` still answers for it.
- Sign-in: every page asks who you are at `/login`, and a person from the map's people who has no password yet chooses one there (at least 8 characters, kept scrambled in `~/.anur-living-map/users.db`, outside the repo). A signed-in browser acts only as that person. `node users.js set <name>` changes a password; `list` and `remove <name>` too. The API stays open to this Mac's own tools (Claude's plans, the listeners).
- Sign in with Google: the button sends you to Living Map login (`../login/`, on Cloud Run in the GCP project `living-map-login`), and anyone with a Google account gets in. You come back signed in as one of this map's people when your Google name matches one (full name or first name), else under your Google name; a Google address on the login's list signs in as the name kept there. The map itself stays on this Mac. `LIVING_MAP_LOGIN_URL` points at another login service; set it empty to turn Google off. A name and password kept there (for someone with no Google account) also works in the sign-in form.
- Drawing by hand: the Box tool in the dock drags out a box at the size you drag (a click makes one the usual size) and you name it inside that shape; a picked box shows a handle on each corner to resize it; the Line tool drags from one box to another, then takes the words on the line; Pan drags the map from anywhere. A box's card ends in Delete this box (the card asks for confirmation; Delete on a selected box removes it immediately and selects its parent), which asks once, then takes the box and its lines off the map for everyone; History brings it back. A click on a line picks it (it turns blue), and Delete line beside it or the Delete key removes just that line; Claude removes one with `remove_lines` in `living_map_change`, or `unlink` in a chat's change. Level − + goes down to level 0, only the start box: the top-level box, in orange (with several, the one with the most boxes under it; on a new map, the first box).
- Share ▸ Share as a file downloads the map as one Markdown file (`<map name>.md`): every box with its notes and decisions, the lines, and what still waits on an answer.
- The faces at the top right are who has this map open right now; the menu under them says who is here and who is not.
- It keeps itself current: run from a git clone on `main` with no changes of its own, the server looks at GitHub when it starts and every ten minutes, pulls what is new, refreshes the skill's copy under `~/.claude/skills` and starts itself again in its place; pages and listeners reconnect by themselves. A copy without git (`npx anur-living-map`) is left to npx.
- Any Claude Code chat on this Mac, in any folder, can read and change a map with two tools from `mcp.js`: `living_map_read` and `living_map_change` (boxes, lines, to-dos and questions for a teammate, many in one call, boxes named by id or by name). Registered once with `claude mcp add --scope user living-map -- node <path>/mcp.js`; `LIVING_MAP_URL` points it at another server.

A test copy of the server (an agent checking a change) runs on another port, such as `node server.js 4399 --project <repo>`: port 4323 is the team map people have open, and a copy started there takes its place with empty maps.

Without `--project`, the map is the plan-first story from `seed.json`; Codex and the merge check in that story are staged.

Cmd+V selects the pointer tool and Cmd+H selects the Hand tool when you are not typing in a field.

Drag a topic near a different parent to see a green parent outline and landing box. Select multiple topics with a selection rectangle to drag and attach their branches together in one undoable move. Selecting a parent and its child carries that child only once. The original branches and their lines stay still with light-blue outlines; a translucent copy with its box outline and wrapped label previews the landing until release. Release to attach the topic and its children there, replacing its old parent connection. Nearby branches make room for the moved branch, and Cmd+Z restores the move and its connection together. Move away to keep dragging freely, or press Escape to cancel. Free drops carry the children too and settle at the nearest clear vertical position, leaving space around existing boxes. Attachment previews also check disconnected boxes and the full label dimensions. Tidy up sits at the top-right of the canvas, beside the sidebar. A topic cannot attach to itself, its descendants, or a locked box. The Information header keeps Side Chat on one line while renaming a box.

Cmd+A selects the Line tool; Cmd+C selects Comment. Ctrl works on other keyboards. Text fields keep normal select-all, copy and paste.

Keyboard brainstorming: Cmd+R opens an unconnected Topic as a selected draft. A click selects its topic immediately, so Tab branches from that topic even before its details card opens. Clicking the selected topic keeps it selected, and an older save cannot replace a newer selection. Tab creates a Sub-topic; Enter creates a sibling (a child when the selected box is a root). New boxes start selected; typing replaces the default name. Tab, Enter, clicking away, and arrow-key navigation keep the topic. Typing replaces the draft label, and the parent arrow is visible immediately. Delete, Backspace, or Escape dismisses an untouched draft in one press. Tab and Enter accept the default name and immediately select the next draft, so you can keep building without naming each box. Incoming live updates recalculate an open draft against the latest box positions, preserving its text and parent connection. A second Tab keeps the saved child and continues from it, even after a pause; cancelling restores the latest saved positions. With no selection, Tab uses the last selected box in this view, then the starting box; an empty map opens Topic. Keyboard selection keeps the details panel closed. Names stay centered as the box expands outward, and wrap onto as many lines as needed while typing and after saving. The editor grows with its text. Tab, arrow navigation, and deletion keep the camera still while the selected box fits; at an edge, the map pans only far enough to reveal the whole box, keeping the current zoom. While naming, Tab and Enter save and continue to the next topic; Escape cancels and returns selection. F2 edits a selected name; double-clicking the title on a box edits its name, while double-clicking the description edits only that description in place. Enter or clicking away saves; Escape cancels. Clearing a description keeps the box. Proposed boxes support both edits before Apply. Arrow keys select the nearest visible box in that direction, including from an untouched draft (which is saved when you leave it). Horizontal navigation toward a parent selects that parent; Tab there appends another child within that branch. Later sibling branches move down together, including their children, to make room; the parent stays centered over its children. Cancel restores their positions, and undo treats the new topic and shifted boxes as one edit. Once typing starts, arrows move the text cursor. Delete or Backspace removes a selected box and selects its nearest remaining sibling, keeping it visible. Repeated deletion works through the children before returning to their parent (or the nearest remaining box for a standalone topic); inside a name they edit text normally, and deleting an empty name removes that box. Text fields keep their normal shortcuts. Deleting a parent asks for confirmation and removes the whole branch, including folded and nested subtopics. The confirmation shows its question above the Delete and Keep buttons, above nearby topic boxes. Enter confirms; Escape keeps the branch. Leaf boxes and selections with no additional descendants delete immediately. Cmd+Z undoes map edits; Cmd+Shift+Z redoes them (Ctrl on other keyboards). A whole branch deletion is one step. Text fields keep their normal text undo. Up to 100 edits per person are available until the server restarts; unrelated changes by other people are preserved, and conflicting edits block undo. History also restores removed boxes.

Small pointer movements within four screen pixels remain a click, at every zoom level; dragging begins only beyond that distance. Clicking a box updates its highlight and details without rebuilding the boxes or lines, including on the first click. Switching between boxes keeps an open details pane in place, so the canvas does not widen and shrink during the double-click delay. Double-click still edits the name or description, and Tab can immediately add a child to the selected box.

Tidy up uses compact topic spacing: 70px between columns and 35px between short boxes. Taller names reserve more vertical room, and words on connections can widen their gap. Branch order and sides stay the same; repeating Tidy up keeps the layout stable.

Trackpad pinch zoom follows the gesture distance, calibrated to a 4% zoom-in change per pixel of wheel delta, with smaller fractional movements and a cap on large jumps. Zoom stays anchored under the pointer. Two-finger scrolling pans the map.

Share → Copy link copies the current map address and confirms when it is on the clipboard. Owners choose view or edit beside “Anyone with the link can”. Copying the first link enables view access by default; choosing edit enables editing. Enabling a link creates an unguessable address that works without signing in. View links cannot save changes; edit links allow map edits and comments, but cannot change access or run Claude. Revoking link access invalidates existing links; enabling access again creates a new link. Permission changes refresh open link visitors. Private chats and link secrets are excluded from guest data and downloaded files. The address opens this local server on this Mac; it does not publish the map online. Saved map files omit Copy link because they do not have a hosted address.

Share → Export image downloads a PNG of the full current view, including off-screen boxes and lines. The image preserves wrapped names and map colors, omits editing controls and selection highlights, and keeps the current folding and level. Large maps are scaled down to keep the image within browser limits.

While waiting for a reply, the main chat and side chats say “Claude is working…” beside the elapsed time. Linked chat activity keeps its specific step description when one is available.


Password recovery: on the sign-in page, **Set up recovery email** asks for your current local password and sends a verification link. You can also reach it from the people menu. After verifying, **Forgot password?** sends a one-use reset link, valid for 15 minutes. Open email links on the Mac running this map. Changing the password signs out existing browsers and invalidates outstanding recovery links. Recovery applies to passwords kept on this Mac; Google and centrally managed passwords keep their own sign-in paths.

Email delivery uses Resend, with a separate sender configured by `RESEND_API_KEY` and `LIVING_MAP_MAIL_FROM`, or a private `~/.anur-living-map/mail.json` containing `key` and `from` (permissions `0600`). `LIVING_MAP_MAIL_CONFIG` can select another private file. Use an address on a verified sending domain. Never put credentials in the checkout. Until a sender is configured, the recovery form explains that email recovery is not set up. Recovery addresses, hashed expiring tokens and request limits live beside passwords in `users.db`; unknown and unverified usernames receive the same reset-request message.

The team map keeps users, sign-in links, cloud and mail config, logs and the running revision in `~/.anur-living-map`. A Mac that set it up before that folder existed has them in `~/.living-map-2` and keeps using it (`data-dir.js`); nothing is moved.

Use the Box metadata icon beside the box panel’s close button to see who created the box and when it was created and updated. It also shows who last edited the box and its source, with a link when the originating chat is available to you. The panel shows the stable box ID and, for nested boxes, which box contains it. Times appear in your local time. Boxes without recorded details show “Not recorded.” Opening the panel does not change the dates.

Undo and Redo buttons sit in the bottom toolbar, with ⌘ Z and ⌘ ⇧ Z beneath their icons. They use the same map history as the shortcuts and wait for any name being saved. The toolbar moves above the other map controls when there is not enough room beside them.

Double-click a box's title at the top of Information to rename it there. Enter or clicking away saves; Escape cancels. Live updates keep the name being typed in place. Renaming updates the same box on the map and its Updated date, and can be undone or redone.

In Share, owners can remove a member from this project. Removed members disappear from its people list, their open connection closes, and the server blocks their page, map data, edits, downloads and history. Removal survives restarts and map resets. Owners cannot remove themselves or another owner. Removed people are no longer listed in Share. Other team members retain access; Share lists individual people without a general team-access row. This is per-project browser access on the loopback server; the Mac's existing local command-line tools retain their trusted access. Private map files are not served as static browser assets.


Cloud sharing: when this Mac has a cloud service configured, Share → Copy link uploads the map and copies an HTTPS link. “Anyone with the link can” controls View or Edit, and Turn off link revokes access. Shared maps remain available while the Mac is off. Boxes, lines, descriptions and comments sync both ways when it reconnects; a conflict keeps both copies and shows an error in Share. Private chats, pending proposals, local paths and sign-in records stay local. See `../cloud/README.md` for deployment and limits. Without cloud configuration, links still point to this Mac and Share says so.

Auto plan reads the entire map the person can access, including descriptions, decisions, questions and every descendant, whether it starts from a parent or a leaf. It asks one specific clarifying question only when essential information is missing and different answers would materially change the plan; otherwise it proceeds using the available context. Answers in Side Chat continue the original request with that clarification and the whole map. It looks for gaps in the selected branch without repeating topics already covered elsewhere. Suggestions can attach to the selected box or an existing descendant, so a missing role can appear under Categories. Apply rechecks the destination and duplicates against the current map; invalid destinations are dropped instead of moved to the selected box.

Auto plan proposals classify each new box with `boxType: "topic" | "action"`. Topics organize information or decisions. Actions carry a validated `task`: goal, result, destination, inputs, steps, completion evidence, prerequisite Action IDs, readiness (`ready`, `needs_information`, `waiting`) and blockers with who can resolve them. A specific, checkable result makes an Action; missing information does not make it a Topic. Additions can form deeper branches within the selected branch, without an arbitrary target count. Missing or inaccessible prerequisites, dependency cycles and invalid parents are dropped on proposal and checked again on Apply.

Apply creates real, private Action drafts with their instructions already filled in. It does not call Claude or execute work. Open the Action in Side Chat, review its task details and choose **Prepare**. Prerequisites must have confirmed completion with evidence for their current task before preparation or Execute; dependent Actions show **Waiting on a dependency** and return to a draft when those prerequisites finish. Independent Actions can proceed. Preparation may ask a focused question, and keeps the plan and answers for retry. It checks required tool names against the actual runtime catalog and tool discovery, rather than trusting the planner's readiness claim.

For a map owner, preparation loads the execution project's configured tools. A permission hook allows only file reads/search, web lookup, tool discovery, the supported Gmail read tools and map-context reads. Every other call is denied during preparation, including tools allowed by existing settings. Nonowners retain the restricted read-only catalog. Unavailable tools or denied lookups prevent a ready brief. Execute retains normal execution permission checks, so tool availability is not a guarantee that a later write will be allowed. Actual execution results and their evidence are attached to the Action's Side Chat; retries resume the existing execution chat and check finished work before doing more.

Auto plan starts reading the whole map immediately, without a mandatory goal question. If clarification is needed, reply in Side Chat to continue planning. Proposed topics append after existing children in their branch and use the same columns. The preview shifts later branches down only as needed; Apply keeps those positions and Not now restores the existing layout.

Action box: select a saved topic and turn on the **Info box / Action box** toggle at the top right of its details pane. The label shows the current type. Before anything is written in it, turn it off to return to an Info box; after that, **Cancel Action** (before execution) sets it aside as **Cancelled**, keeping its instructions, answers and versions, and **Prepare again** makes it a draft with its instructions. **Action history**, folded under the Action's header, lists every step the map recorded, newest first: who did it and when, the tools a ready brief and a run were given, how a run ended and how long it took. None of it comes from Claude's words. Box metadata shows the latest step. Write what you want done in **Side Chat**, then press **Enter** or the send arrow. Every stage keeps the name **Action box** and the muted plum box style. New and proposed Action boxes have no status pill until preparation starts. A status pill shows **Preparing**, **Needs clarity**, **Waiting**, **Ready to execute**, **Executing**, **Executed**, **Done, unverified**, **Blocked**, **Cancelled** or **Unconfirmed**. Only a run the map saw finish gets the green **Executed** pill: an email the run sent to the brief's exact recipient, or a pull request GitHub confirms, read from the tool calls the run actually made. When Claude reports a task done that the map could not see, it reads **Done, unverified**, with Claude's account shown apart from the map's confirmation, until its author presses **Confirm done**. Continue tells Claude what the map saw the run already do, so nothing is repeated. A **build** Action never works in the project's own checkout: on Execute the map makes a new branch from the default branch, in its own worktree under the team map's data folder, and runs Claude there. Claude edits and runs checks but cannot push or call `gh`. When it finishes, the map commits the changes, pushes the branch and opens the pull request, which is the run's confirmation. With no change, no remote, or a remote that is not GitHub, the map says so and leaves the branch. An Admin can **Hand over** an Action to another member who has opened the map and can see its box, except while it is preparing or running. Only the new author can then take it on, and its history records who handed it to whom. Ready actions have an **Execute** button beneath them. Preparation runs in the background using the whole accessible map, the topic's Side Chat and readable project files. It cannot send messages or change files. Missing details appear in Side Chat, with the **Needs clarity** pill on the map box. Questions and answers stay in that conversation. Enter submits your action or answer; Shift+Enter adds a new line. Once the goal, destination, steps and expected result are known, its pill reads **Ready to execute** for review. Email tasks include the exact recipient, subject and message. **Revise** saves the previous reviewed draft as a versioned Markdown file in the Action chat. Download its filename or expand **View document** to read and copy it; saved versions remain through preparation, execution and refresh. The next preparation receives the prior draft with your requested changes. **Execute** runs `claude -p` in the background with configured tools and automatic permission checks, streams its words into Side Chat and keeps its final response there. It never opens the desktop app. **Continue**, with an optional reply, resumes that exact saved chat with `--resume`, including after a refresh or server restart. It never silently starts a fresh chat if a resume fails. Stop interrupts the process; the response describes what actually happened, including missing access, rather than treating process exit as task completion. Old desktop handoffs load as unconfirmed and are never rerun automatically. Only the person who prepared the action can answer, revise, cancel or execute it. Preparation can be cancelled or retried; a changed box must be prepared again. Action details stay local and are excluded from guest links, downloaded map files and cloud sharing.

Execution results distinguish **Executed**, **Needs your answer**, **Blocked** and **Completion unconfirmed** in Side Chat. Successful results show a short summary with **View details** for the full reply and supporting confirmation, plus an **Executed** pill on the map box. Executed requires a structured confirmation with concrete evidence; a normal process exit alone does not count. Older desktop handoffs load as unconfirmed and offer **Execute here**, which checks for prior work before finishing anything remaining. A Sent-folder record confirms sending, not inbox delivery.

Search map in the top bar finds box names, descriptions and notes across accessible boxes, including folded branches, proposed boxes and boxes inside another box. Open it with Command/Ctrl+F, use the arrow keys to immediately reveal and center each matching box while search stays open. Enter or clicking a result closes the list and opens its Information panel; Escape closes search. Searching does not change map content.

Share shows Local only before publication and Shared online after upload. Copy link asks before the first cloud upload: Keep local cancels without uploading or copying, and Upload and copy link publishes the shared copy. Revoking link access shows In cloud · link off because the cloud copy remains stored. Unknown status and upload failures never imply that publication succeeded.

### Context from other maps

Brain lists other accessible maps in the expandable **Include other maps** list, collapsed by default with every map unchecked. The list stays open while you check or uncheck maps. Check a map to include it as extra context for this map; selections persist across refreshes and restarts. Map Chat, Side Chat, Auto plan and Action preparation receive descriptions and read access only for checked maps: purpose, topic excerpts, decisions, unanswered questions and remembered context. Claude chooses whether to load a relevant map's objects, decisions or memories through read-only tools; additional pages and description search are available for larger collections. Replies show **Read from** links for maps actually loaded. Standalone linked Claude Code tools can browse accessible maps independently through `living_map_catalog` and `living_map_load`. Other maps are reference material, not instructions or edit targets. Private chats, linked transcripts, action runs, local paths and share credentials are excluded. Access is checked on every read, and the capability expires when the answer finishes.

In **Brain → Map description**, edit the purpose, scope and background for other maps to discover. **Description used by other maps** previews the description, automatically rebuilt from that background and the latest map content without a separate model call. Large descriptions explicitly indicate additional boxes; search includes the complete accessible map content.

### All brain

The home page at `/` includes **All brain**, listing the maps you can access. Choose a map to view or download its Description object, Map object, Decision object and Memory object as JSON. Open map sits beside the map name. Shared links and downloaded files do not expose this cross-map browser.
